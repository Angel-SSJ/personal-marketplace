# Foundations and lifecycle

## Concepts

Inbox is a trusted temporary collection of unclarified inputs. Capture is preserving enough context to revisit an input; it does not accept an obligation. Clarification decides what an input means. Incorporation places useful material in its proper existing home. A held package has a known intended home and a real dependency preventing incorporation. Incubation is a conscious decision not to activate a possibility now; it is distinct from unresolved capture or staging.

## Principles and theoretical status

Separate action reminders from support files, preserve provenance, minimize duplicate authority, prefer use over collection volume and keep processing cost proportional to value. These are workflow principles and user policies, not mathematical theorems. The numbered storage layout and strict hold criteria are this user's implementation, not universal PARA/CODE/GTD doctrine.

## Pipeline and conditions

Capture -> inspect and clarify -> check useful contribution and existing entities -> route reminders/support -> incorporate and verify, or retain a justified hold -> weekly/event review -> incorporate when unblocked. Discard is a proposal requiring explicit deletion authority, not an automatic terminal action. Stages loop as evidence changes; not every item needs a task, project, summary or full method cycle.

Unknown -> clarified nonactionable reference, incubated possibility, or actionable commitment. Independently, a support file becomes directly filed or temporarily held. Ready for incorporation is not completed project status. Empty Inbox means clarified/routed, not all resulting work done. A hold losing its justification must be reassessed, not silently renewed or auto-deleted.
