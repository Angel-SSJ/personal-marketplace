# Just-In-Time knowledge-work packets

## Responsibility

CODE owns discovering and shaping useful intermediate contributions when turning knowledge into work. This module is about the work, not how to polish a task title. GTD still owns actual commitment/actionability decisions; PARA owns support location; task-writing can express a selected action, finish condition, or pause cue without re-deciding it.

An intermediate packet is a bounded useful output, such as a supported comparison, outline, calculation, sketch, draft passage, or prototype. Its value is that it advances a real purpose and can be understood or reused; it is not just an arbitrary slice of elapsed time.

## Just-In-Time decomposition

1. Establish the actual purpose and current question or contribution. Inspect existing material and work already available.
2. Identify the smallest meaningful contribution needed now. Keep speculative later steps in support instead of expanding every imagined subtask into active work.
3. Determine the contribution's practical finish and the information/prerequisites actually needed. Distinguish known dependencies from missing facts.
4. Produce the packet and use its result/feedback to discover the next useful contribution when needed. Do not require full up-front decomposition or a complete summary of all captured knowledge.
5. Return any accepted next action to the commitment system and preserve useful work/context under the storage profile. A packet proposal does not itself create a commitment.

## Existing personal size guide

The user's earlier task policy used roughly 15 minutes–3 hours for substantial intermediate packets. This is retained here as a local sizing guide, not a universal CODE law, a default duration, or a minimum for all actions. A naturally three-minute call or four-minute request remains valid. Do not pad work, invent substeps, or reserve a calendar block to fit the range.

If a contribution is too large to resume or finish usefully, identify a smaller meaningful result. If further splitting destroys its usefulness, expose the trade-off rather than force tiny fragments. Size is an estimate to assess work, not a deadline or schedule.

## Pause and resumption

When interrupted, determine the substantive state of the contribution: what is established, the unresolved issue or blocker, and the actual resumption point. Preserve source context and a selected next step when one exists. An unknown next step remains unknown until clarified.

The state cue can live in existing task/support context without a prescribed file or section. task-writing may make its expression concise, but does not decide the work state or create a new packet. At reuse, check currency, provenance, and applicability before treating an old packet as ready evidence.

## Boundaries and audit cues

Watch for speculative task-tree growth, time-only fragments without useful outputs, padding short actions to hit a quota, or polishing reminders before anyone has decided the intended contribution. Repair the missing work decision here; route actual actionability to GTD and pure wording to task-writing. No repeated full review is necessary for one packet.
