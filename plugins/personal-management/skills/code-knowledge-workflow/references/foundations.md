# CODE foundations

## Concepts

CODE is Tiago Forte's Capture, Organize, Distill, Express framework for turning external knowledge into useful creative work. It is a set of cooperating practices; useful work may begin with an existing draft and loop back to a specific information gap.

| Stage    | Purpose                                              | Useful decision                                                         | Failure to avoid                                                    |
| -------- | ---------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Capture  | Preserve information worth encountering again        | Does this resonate, answer an open question, or support a real purpose? | Saving everything as insurance against uncertainty                  |
| Organize | Make information available where it will be used     | Which active outcome, responsibility, or useful topic benefits?         | Filing only by abstract subject while active work remains scattered |
| Distill  | Make the valuable part easier to recognize and reuse | What matters for this use, and what context must survive?               | Mandatory up-front summarization or context-free compression        |
| Express  | Turn ideas and evidence into a useful contribution   | What is the smallest meaningful thing I can make with this?             | Perpetual consumption without an output or decision                 |

**Resonance** is a practical capture signal: surprise, usefulness, personal relevance, an illuminating example, or a connection to a live question. It is not a requirement to prove utility before capturing anything. **Discoverability** means recognizing the relevant idea quickly; **understandability** means retaining enough context to interpret it correctly. Good distillation balances both.

An **intermediate packet** is a bounded, reusable piece of work such as an analysis, explanation, calculation, outline, sketch, or prototype. It can make progress before a whole project is complete. It has no mandatory file format or duration. A **status summary** is an optional resumption cue about the state of work and its next decision; it is not a universal required document section.

## Principles

1. Externalize what is worth revisiting so memory can support thinking rather than carry every detail.
2. Capture selectively; resonance and current questions are useful filters. Capture can remain lightweight and imperfect.
3. Organize for actionability. PARA supplies the supporting-information structure without deciding which commitments to accept.
4. Distill opportunistically. Invest more attention when material is revisited for an actual use.
5. Make small useful outputs early. Creation and feedback can reveal what research is still necessary.
6. Preserve context and provenance. Compression should reduce retrieval effort without changing the meaning of the evidence.
7. Alternate divergence and convergence deliberately. Explore options when the question is open; narrow scope when producing a specific deliverable.
8. Let reusable knowledge compound. Reuse existing intermediate work when it is relevant and still valid.

## Progressive Summarization

| Layer           | Transformation                                                 | When useful                                                     |
| --------------- | -------------------------------------------------------------- | --------------------------------------------------------------- |
| Original source | Full material or a retrievable source                          | To inspect the underlying context and evidence                  |
| Layer 1         | Selectively captured excerpts or notes                         | Initial capture of material worth revisiting                    |
| Layer 2         | Emphasize important passages within the capture                | First meaningful reuse when scanning is costly                  |
| Layer 3         | Highlight the most salient ideas among the emphasized material | Further reuse that benefits from faster recognition             |
| Layer 4         | Express the main ideas concisely in one's own words            | High-value material that merits a synthesis                     |
| Layer 5         | Remix material into new work                                   | A real output benefits from integration and original expression |

This is a layered technique, not a checklist every note must complete. Many captures can remain at Layer 1 indefinitely. Layer 5 overlaps Express. Exact proportions, counts of highlights, and word lengths are not requirements. Keep original context accessible rather than destructively replacing it with the shortest layer.

## Conditions and lifecycle

A capture can wait unused, be recruited by a project, be selectively distilled, become part of an output, return as reusable knowledge, or become inactive. Current purpose determines the next stage. Material without a current purpose may remain useful reference; it is not automatically overdue work.

Start new research when a real unresolved question prevents progress. Stop collecting when existing evidence is sufficient for the present decision/output at the needed confidence, or when further collection exceeds the agreed scope. If evidence remains insufficient, narrow the claim, mark the gap, or ask for the necessary research rather than presenting speculation as fact.

## Theoretical status

CODE and Progressive Summarization are practitioner frameworks, not formal theorems. Claims about cognitive offloading, attention, creativity, or compression describe practical mechanisms and possible benefits; this package does not claim medical, cognitive, or productivity guarantees. Personal layer-use percentages and preferred packet durations are anecdotes, not general thresholds.

The process does not establish factual truth by repetition, resonance, or summary. Evidence still needs context and appropriate verification. The local audit and coordination policies are implementation choices, not additional canonical CODE laws.
