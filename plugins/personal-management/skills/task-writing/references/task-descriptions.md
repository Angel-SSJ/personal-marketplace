# Descriptions, finish conditions, support, and pause cues

## Express the current action's finish

State its supplied or unambiguously implied done condition in one concise line. Distinguish “the invitation draft is ready for review” from “the event is complete”. Do not invent acceptance criteria, broaden scope, require a particular file, or mark the action completed merely because its description improved.

When the finish cannot be determined from the person's stated intent, ask what would count as this action being done or mark that decision unresolved. A writing suggestion is a proposal, not a newly accepted deliverable.

## Support references

Retain a real accessible support reference when supplied. Its purpose is to connect the reminder to useful context without duplicating source material. If missing or broken, label the gap; do not invent paths, create empty support files, or block otherwise executable work solely because metadata is missing.

Finding the correct information home belongs to PARA; creating or distilling substantive support belongs to CODE or the actual work. This module can express a pointer after that decision, not prescribe folders or validate the support document's sections.

## Pause and resumption wording

When asked to express the state of paused work, write a concise Status Summary/Freeze Note from known facts: current state or resumption point, unresolved issue, and selected next step if known. If the next step is unknown, say so rather than select it.

The cue can remain in the task description or point to existing linked support. Do not require a named file or mandatory section in a document. Keep the latest useful state without accumulating a duplicate diary. CODE owns the substantive work-state/packet decision; this module improves the cue's expression.

## Output shape

Give the revised description or cue, the real reference if available, and only the gaps needed to preserve meaning. The one-line finish plus reference/pause information is a task-expression convention, not a compulsory serialized schema. Use no empty template fields for facts irrelevant to the request.
