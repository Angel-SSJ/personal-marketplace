# Timebox and duration representation

## Existing policy and distinct meanings

The accepted personal policy permits discretionary calendar blocks only for protected habits or genuine batches of similar work, not micro-scheduling flexible individual tasks. A real appointment is a different kind of constraint. This is the user's policy, not a universal GTD rule.

Distinguish a supplied effort estimate, a reserved block, an appointment, a start trigger, and a hard deadline. Express the actual meaning; an estimate does not reserve time. Relabeling one flexible action as a “batch” does not change what it is.

## What this module does

Improve the description of an already chosen block, habit, batch, or estimate. Retain its actual duration, participants, or recurrence when supplied. Flag wording that confuses an estimate with a reservation or disguises a single task as a batch, without rescheduling or deciding what deserves a block.

If only “30 minutes” is supplied, ask whether it is an estimate or a chosen block if that distinction matters. Do not infer a start time, recurrence, duration, or allocation. There is no default block duration, daily quota, or schedule-generation algorithm here.

## Ownership boundary

The person and their chosen planning/execution workflow decide whether to reserve a permitted block, batch work, or select an action. CODE owns useful packet decomposition; GTD owns engagement and actual calendar constraints. This skill expresses those decisions and surfaces missing facts. It never stretches a short action to fill a block, generates a micro-itinerary, or creates calendar events as an implicit side effect of writing.
