# Task-expression audits

## Scope

Inspect a bounded set of task records for clarity and fidelity to supplied intent. Audit representation, not whether the person chose the right commitments, next action, priority, calendar plan, methodology, or storage location. A request to audit a whole workflow needs its method specialist.

## Checks

| Representation issue              | Evidence                                                                                       | Minimum writing repair                                                                                   |
| --------------------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Vague title                       | Reader cannot recognize the intended supplied action/object                                    | Rewrite known meaning or ask for the missing action; do not invent it                                    |
| Action/outcome/waiting confusion  | Wording implies executable work while the supplied record is an outcome or dependency          | Express the supplied distinction or flag a contradictory label for GTD/user clarification                |
| Unclear finish                    | Action finish is confused with project completion or absent                                    | Express known done condition in one concise line; mark missing acceptance decision                       |
| Support gap                       | Link absent/broken or context duplicated needlessly                                            | Preserve a real pointer or flag the gap; do not move files or create compliance artifacts                |
| Poor pause cue                    | Known resumption point is buried or ambiguous                                                  | Rewrite current state/unresolved point/selected next step; retain unknowns                               |
| Tag not permitted                 | Candidate is absent from current JSON, not lowercase, or used before approved persistence      | Follow the format/approval/update flow; do not use an unapproved candidate                               |
| Priority not permitted or unknown | Value absent from current JSON, inferred from old labels, or missing data defaulted to a value | Preserve only valid supplied membership and flag the missing/invalid decision; do not rank or add levels |
| Date/timebox confusion            | Estimate, preference, review trigger, and true deadline/reservation are conflated              | Clarify supplied type without inventing a date, slot, or duration                                        |

## Findings and closure

Give the observed wording problem, its likely interpretation cost, the faithful edit or specific missing fact, and how to retest clarity. Scale detail; a title edit needs no full audit template. Flag inferred meaning instead of asserting it as fact.

Retest whether a reader can understand the supplied intended action and its state without reconstructing it. Confirm no commitment, owner, date, priority, dependency, or readiness changed silently. Separate proposed wording from actual edits and verified writes.

Recurring ambiguity can justify a focused representation check, not a new daily full-system audit. If repairing it requires deciding work rather than expressing it, stop at that boundary and route the decision to the appropriate owner.
